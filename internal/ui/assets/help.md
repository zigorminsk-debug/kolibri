# Быстрый старт

Kolibri Forge связывает локальную модель Колибри с GitHub: вы описываете задачу, модель пишет код, программа отправляет его в репозиторий, GitHub Actions собирает программу, а готовые файлы скачиваются на ваш компьютер.

## Пять шагов

1. Запустите сервер Колибри. Индикатор «Колибри» в шапке станет зелёным и покажет имя модели.
2. Войдите в GitHub: нажмите на индикатор «GitHub» или откройте «Настройки» и вставьте токен.
3. В поле «Репозиторий на GitHub» введите `владелец/название` или нажмите на лупу и выберите репозиторий из списка. Если такого репозитория нет, он будет создан.
4. Выберите тип проекта и системы, для которых собирать, и опишите задачу в поле «Что нужно сделать».
5. Нажмите «Запустить» и следите за ходом работы справа.

Когда сборка пройдёт, появится зелёная плашка «Программа собрана» с кнопкой «Открыть папку».

## Чего ждать по времени

Локальная модель отвечает медленно: ответ с кодом может идти от нескольких минут до часа и дольше. Сборка на GitHub обычно занимает от двух до десяти минут. Программа ждёт сколько нужно, окно можно свернуть.

# Что нужно для работы

## Сервер Колибри

Это программа colibrì, которая запускает языковую модель на вашем компьютере. По её инструкции сервер запускается файлом `START-HERE.bat` на Windows или `./start-here.sh` на Linux и macOS и слушает адрес `http://127.0.0.1:8000`. Этот адрес уже стоит в настройках.

Если сервер запущен на другом компьютере или порту, укажите его адрес в «Настройках». Если сервер запущен с ключом `COLI_API_KEY`, впишите тот же ключ в поле «API-ключ».

## Аккаунт GitHub и токен

Программа записывает код в ваш репозиторий и читает ход сборки, поэтому ей нужен токен доступа:

- classic-токен — с областями `repo` и `workflow`;
- fine-grained-токен — с правами Contents и Workflows (Read and write) и Actions (Read).

Без права `workflow` GitHub не даст записать файл сборки, и работа остановится на коммите. В «Настройках» и в окне входа есть ссылка, которая открывает страницу создания токена с уже отмеченными областями.

В репозитории должны быть разрешены GitHub Actions. В новых репозиториях они включены; если в организации они запрещены, программа скажет об этом и покажет, где их включить.

## Интернет

Колибри работает локально, а для GitHub нужен интернет: отправка кода, наблюдение за сборкой, скачивание готовых файлов и проверка обновлений идут через `api.github.com`.

# Вход в GitHub и выбор репозитория

## Окно «Вход в GitHub»

Оно открывается само, если токена нет или GitHub его не принял, а также по нажатию на индикатор «GitHub», когда тот сообщает о проблеме. Войти можно двумя способами.

**Токен.** Вставьте токен в поле и подтвердите. Ссылка рядом открывает нужную страницу GitHub.

**Через браузер, без токена.** Программа показывает короткий код, вы вводите его на странице `github.com/login/device` и подтверждаете доступ. GitHub разрешает такой вход только зарегистрированным приложениям, поэтому сначала создайте своё: GitHub → Settings → Developer settings → OAuth Apps → New OAuth App, включите в нём «Enable Device Flow» и вставьте его Client ID в «Настройках». Пока Client ID не задан, в окне входа есть только токен.

Токен в обоих случаях сохраняется в файле настроек на этом компьютере. Файл доступен только вам.

## Выбор репозитория

Лупа в поле «Репозиторий на GitHub» открывает список ваших репозиториев — личных и тех, куда у вас есть доступ. В списке работает поиск по названию и описанию; у каждого репозитория видно, приватный ли он, архивный ли и можно ли в него писать. Кнопка «Сменить аккаунт» открывает окно входа.

При выборе репозитория поле «Ветка» очищается: работа пойдёт в основной ветке, её имя показано в поле подсказкой.

## Новый репозиторий

Если репозитория с таким названием нет, программа создаст его в вашем аккаунте. Галочка «Новый репозиторий — приватный» определяет, будет ли он закрытым. На уже существующие репозитории галочка не влияет.

# Новая задача

## Поля формы

- **Репозиторий на GitHub** — в виде `владелец/название`.
- **Ветка** — если пусто, работа идёт в основной ветке. Если указать имя, которого нет, ветка будет создана от основной.
- **Тип проекта** — на чём писать и как собирать; см. раздел «Типы проектов».
- **Собрать для** — системы, под которые нужна программа; см. раздел «Системы и Android».
- **Что нужно сделать** — задача обычными словами.
- **Чинить упавшую сборку** — сколько раз модель может исправлять код, если сборка не прошла: от «не исправлять» до пяти раз.
- **Новый репозиторий — приватный** — для репозитория, который будет создан.
- **Публиковать релиз после сборки** — выложить готовые файлы в раздел Releases репозитория.

Форма запоминается: при следующем запуске программы всё будет на месте.

## Как писать задачу

- Пишите, что программа должна делать, а не как её писать: «оконный калькулятор: четыре действия, проценты, история последних десяти вычислений».
- Перечисляйте важное явно: язык интерфейса, тёмная или светлая тема, работа с клавиатуры, формат файлов.
- Одна задача — один понятный результат. Большую программу лучше вести этапами: сначала основа, затем отдельными запусками добавлять возможности.
- Чтобы доработать уже написанную программу, укажите тот же репозиторий и опишите только изменение: «добавь кнопку очистки истории». Модель получит текущий код и журнал работы и продолжит, а не начнёт заново.

## Что модель не может

Модель присылает только текстовые файлы. Картинки, значки, шрифты и другие двоичные файлы она создать не может — положите их в репозиторий сами, и модель будет знать, что они там есть.

# Типы проектов

Тип определяет язык и способ сборки. Правила выбранного типа программа сообщает модели сама — писать их в задаче не нужно.

- **Авто — выберет модель.** Модель сама выбирает подходящий стек; сборка подбирается по файлам, которые она прислала. Если репозиторий уже содержит проект, используется его тип.
- **Go — консольная программа.** Исполняемый файл для терминала.
- **Go + Fyne — оконное приложение.** Программа с окном; единственный тип, который собирается ещё и под Android.
- **Python — исполняемый файл.** Один файл, собранный PyInstaller; Python на компьютере пользователя не нужен.
- **Rust.** Исполняемый файл.
- **C/C++ — CMake.** Исполняемый файл.
- **.NET — C#.** Самодостаточная программа, .NET на компьютере пользователя не нужен.
- **Веб-приложение — Node.js.** Собранный сайт в архиве.
- **Статический сайт.** Архив сайта.
- **Другое — архив исходников.** Сборки нет, GitHub только упаковывает исходники в архив.

Если при типе «Авто» программа не распознала проект, она предупредит в журнале и соберёт только архив исходников. В этом случае выберите тип вручную.

# Системы и Android

## Windows, Linux, macOS

Отметьте галочками системы, для которых нужна программа. На GitHub для каждой запускается отдельная сборка, и для каждой получается свой набор файлов. Для сайтов и типа «Другое — архив исходников» галочки неактивны: результат одинаков везде.

Чем больше систем, тем дольше сборка и тем больше расходуется минут GitHub Actions. Для приватных репозиториев минуты ограничены тарифом, а сборки под macOS и Windows расходуют их быстрее.

## Android

Четвёртая галочка — Android. Под него собирается только тип «Go + Fyne»:

- при типе «Авто» с галочкой Android модель напишет программу на Go + Fyne и получит правила для телефона: одна колонка, прокрутка, всё доступно касанием;
- для остальных типов галочка неактивна. Если проект в репозитории уже другого типа, он соберётся под остальные отмеченные системы, а в журнале появится предупреждение.

Получается файл `.apk`. Он лежит в папке сборки, а при включённом релизе — ещё и в релизе на GitHub, откуда его удобно скачать прямо с телефона. При установке телефон попросит разрешить установку из неизвестных источников.

Что стоит знать об этом APK:

- он подписан отладочным ключом — для своего телефона этого достаточно, для Google Play нет;
- в него входят сборки для 64- и 32-битных ARM, то есть для телефонов и планшетов;
- номер версии растёт с каждой сборкой, поэтому новая сборка ставится поверх старой;
- значок берётся из файла `Icon.png` в корне репозитория; если его нет, подставляется стандартный.

Одну и ту же программу можно собирать сразу и под компьютер, и под Android: отметьте, например, Windows и Android.

# Ход работы

## Этапы

Вверху справа — пять этапов. Текущий подсвечен, пройденные отмечены галочкой.

1. **Подготовка.** Проверяется связь с Колибри и GitHub, при необходимости создаются репозиторий и ветка, читается текущий код.
2. **Код от модели.** Задача уходит модели, ответ появляется по мере генерации.
3. **Коммит.** Файлы из ответа записываются в репозиторий одним коммитом вместе с файлом сборки и записью в журнале работы.
4. **Сборка.** GitHub Actions собирает программу, программа следит за каждым заданием.
5. **Программа.** Готовые файлы скачиваются на компьютер, при включённой галочке публикуется релиз.

Справа от этапов — время с начала работы и номер попытки, если идут исправления.

## Вкладки

- **Журнал** — всё, что делает программа, с отметками времени. Кнопка «Копировать журнал» кладёт его в буфер обмена, «Журнал на диске» открывает папку с файлом журнала.
- **Ответ модели** — текст, который присылает Колибри, вместе с размышлениями, если модель их показывает. Галочка «Следить за выводом» прокручивает текст к концу.
- **Файлы** — файлы, которые ушли в коммит: новые, изменённые и удалённые. Нажмите на файл, чтобы посмотреть его.
- **Сборка** — задания на GitHub и шаг, на котором сейчас каждое. Кнопка «Открыть на GitHub» открывает страницу запуска.

## Остановка

Кнопка «Остановить» прерывает работу программы. Ответ, который шёл в эту минуту, не сохраняется; всё, что уже записано в репозиторий, остаётся. Сборку, уже начатую на GitHub, кнопка не отменяет — она дойдёт до конца сама.

## Итог

После работы появляется плашка с итогом:

- **Программа собрана** — файлы скачаны, есть кнопки «Открыть папку», «Репозиторий», «Сборка на GitHub» и, если релиз опубликован, «Релиз».
- **Этап собран, работа не окончена** — модель разбила задачу на части; запустите ту же задачу ещё раз.
- **Ответ модели прервался** — сервер замолчал или остановился; сделанное сохранено, запустите задачу снова.
- **Не получилось** — сборка не прошла за отведённое число попыток или произошла ошибка; причина написана на плашке и в журнале.
- **Остановлено** — работу прервали вы.

# Если сборка упала

## Автоматическое исправление

Если сборка не прошла, программа берёт из журнала GitHub место с ошибкой и отправляет его модели вместе с кодом. Модель присылает исправленные файлы, они коммитятся, и сборка запускается снова. Число таких попыток задаётся в поле «Чинить упавшую сборку».

Когда попытки кончились, появляется плашка «Не получилось». Что можно сделать:

- посмотреть ошибку на вкладке «Журнал» или на странице сборки в GitHub;
- уточнить задачу — часто модель упирается в деталь, которую можно упростить;
- увеличить число исправлений и запустить снова: работа продолжится с текущего кода.

## Если не опубликовался релиз

Бывает, что программа собралась, а релиз на GitHub выложить не удалось. Это не ошибка кода: модель не просят ничего исправлять, файлы скачиваются как обычно, а причина показывается в итоге и в журнале. Исправьте причину и запустите задачу снова или выложите скачанные файлы в релиз вручную.

## Файл сборки

Сборкой управляет файл `.github/workflows/kolibri-build.yml`. Его пишет и обновляет сама программа; файлы, которые модель пытается положить в папку `.github/`, отбрасываются. Править его вручную не стоит: при следующем запуске он будет записан заново.

# Большие проекты и журнал работы

У локальной модели нет памяти между запросами, а большой проект не помещается ни в её контекст, ни в один ответ. Чтобы работу можно было вести частями и продолжать после перерыва, программа ведёт журнал прямо в репозитории — файл `.kolibri/worklog.md`.

## Что в журнале

Каждая запись — один шаг: что было поручено, что модель сделала, какие файлы изменила, чем кончилась сборка и что осталось сделать. Запись попадает в тот же коммит, что и код этого шага. При каждом запросе модель получает конец журнала и текущие файлы — поэтому она продолжает, а не начинает заново.

## Когда ответ не дошёл до конца

- **Ответ упёрся в лимит токенов или размер контекста.** Целые файлы сохраняются коммитом без запуска сборки, оборванный файл отбрасывается. Затем модель получает новый запрос с чистым контекстом и указанием дописать недостающее — до шести частей подряд, после чего собирается всё вместе.
- **Сервер Колибри остановлен или замолчал.** Файлы, которые успели прийти целиком, сохраняются, в журнал пишется причина. Запустите задачу снова — работа продолжится с этого места.
- **Модель сама разбила задачу на этапы.** В конце ответа она перечисляет, что осталось; список попадает в журнал. После сборки этапа программа сообщает, что работа не окончена, — запустите ту же задачу ещё раз.

## Правила журнала

Журнал ведёт программа: файлы, которые модель пытается положить в `.kolibri/`, отбрасываются. Когда файл перерастает 200 КБ, самые старые записи удаляются. Не удаляйте журнал из репозитория, пока работа над проектом идёт.

## Журнал на диске

Всё, что показывает вкладка «Журнал», дополнительно пишется в файл `kolibri-forge.log` рядом с файлом настроек: экран очищается при каждом запуске, файл нет. Кнопка «Журнал на диске» открывает его папку. Файл больше 4 МБ переименовывается в `kolibri-forge.log.1` и начинается заново. Токен в журнал не попадает.

# Готовые программы и релизы

## Где лежат файлы

После успешной сборки файлы скачиваются в папку из настроек (по умолчанию `KolibriForge` в домашней папке): `<репозиторий>/build-<номер>/<имя сборки>/`. Для каждой системы — своя папка. Кнопка «Открыть папку» на плашке итога ведёт туда.

## Релиз на GitHub

При включённой галочке «Публиковать релиз после сборки» на GitHub создаётся релиз `build-<номер>`: для каждой системы архив `.zip`, а для Android — сам файл `.apk`. Ссылку на релиз можно отправить другим людям.

## Запуск собранной программы

Собранные программы не подписаны сертификатом разработчика, поэтому система может предупредить о неизвестном издателе:

- Windows — «Подробнее» → «Выполнить в любом случае»;
- macOS — правый клик по программе → «Открыть»;
- Android — разрешить установку из неизвестных источников.

# Настройки

Кнопка «Настройки» в шапке. Настройки хранятся в файле `config.json` в папке `kolibri-forge` системной папки настроек пользователя: `%AppData%` на Windows, `~/.config` на Linux, `~/Library/Application Support` на macOS.

## Колибри

- **Адрес сервера** — по умолчанию `http://127.0.0.1:8000`.
- **API-ключ** — нужен, только если сервер запущен с `COLI_API_KEY`.
- **Модель** — «Первая на сервере» или конкретная из списка. Кнопка «Проверить и обновить модели» спрашивает список у сервера.

## GitHub

- **Токен доступа** — если поле пустое, берётся переменная окружения `GITHUB_TOKEN` или `GH_TOKEN`. Кнопка «Проверить токен» показывает аккаунт и права.
- **Client ID OAuth-приложения** — нужен только для входа через браузер.

## Генерация

- **Температура** — от 0 до 2. Чем ниже, тем предсказуемее код; по умолчанию 0.2.
- **Макс. токенов ответа** — 0 означает «без ограничения».
- **Тишина до обрыва** — сколько минут ждать, если сервер ничего не присылает. Колибри шлёт сигнал каждые 10 секунд, так что долгая тишина означает, что сервер остановился.

## Готовые сборки

- **Папка, куда скачивать программы.**

## Обновления

- **Проверять обновления при запуске** и **Предлагать промежуточные сборки** — см. раздел «Обновление программы».

# Обновление программы

Kolibri Forge публикуется на GitHub в репозитории `zigorminsk-debug/kolibri`. При запуске программа один раз спрашивает у GitHub список релизов и сравнивает его со своей версией. Никакие ваши данные при этом не отправляются, токен не используется.

## Если есть новая версия

Под шапкой появляется полоса «Доступно обновление»:

- **Подробнее** — что изменилось и какая версия у вас;
- **Скачать** — на Windows скачивается установщик, на Linux и macOS — архив; если подходящего файла в релизе нет, открывается страница релиза;
- **×** — убрать полосу до следующего запуска.

В окне «Подробнее» есть кнопка «Пропустить эту версию»: о ней программа больше не напомнит, но о следующей сообщит.

## Как установить

- Windows: запустите скачанный `KolibriForge-Setup.exe`. Он закроет работающую программу и обновит её; настройки и журнал сохранятся.
- Linux и macOS: распакуйте архив поверх старой версии.

Программа ничего не скачивает и не устанавливает без вас.

## Версии и сборки

Полноценные версии имеют номер вида 1.2.0. Между ними публикуются промежуточные сборки с порядковым номером — они свежее, но проверены меньше. Галочка «Предлагать промежуточные сборки» в настройках включает и выключает напоминания о них.

## Проверка вручную

Кнопка «Проверить обновления» есть в «Настройках» и в разделе «О программе» этой справки. Автоматическую проверку можно отключить в «Настройках».

# Вопросы и неполадки

## Индикатор «Колибри · нет связи»

Сервер не запущен или адрес в настройках неверный. Запустите сервер и нажмите на индикатор — проверка повторится. Откройте адрес сервера в браузере: если страница не открывается, дело в сервере, а не в программе.

## Индикатор «Колибри · нет модели»

Сервер отвечает, но в его списке нет ни одной модели — она не загружена. Загрузите модель в Колибри и нажмите на индикатор: проверка повторится.

## Индикатор «GitHub · токен не принят»

Токен отозван, просрочен или вставлен с ошибкой. Нажмите на индикатор и войдите заново.

## Надпись «нет workflow» на индикаторе GitHub

У токена нет права `workflow`. Код отправить получится, а файл сборки — нет. Создайте токен с областями `repo` и `workflow`.

## Работа остановилась на коммите

Чаще всего это права токена (см. выше) или защита ветки в репозитории, которая запрещает прямую запись. Укажите в форме другую ветку.

## Сборка не запускается

В репозитории выключены GitHub Actions: Settings → Actions → General → Allow all actions. Программа пишет об этом в журнале и даёт ссылку.

## Модель долго молчит

Это нормально для больших моделей: до первого слова может пройти несколько минут. Программа обрывает запрос, только если сервер молчит дольше времени из настройки «Тишина до обрыва».

## Модель прислала ответ без файлов

Программа попросит её повторить в нужном виде. Если не помогает, упростите задачу или выберите тип проекта вручную вместо «Авто».

## Сборка под Android падает

Обычно модель использовала то, чего нет на телефоне: запуск других программ, системный трей, несколько окон. Оставьте попытки исправления включёнными — модель получит ошибку и уберёт лишнее. Если задача по сути «настольная», соберите её только под компьютер.

## Программа собралась, а запускается с предупреждением

Собранные файлы не подписаны — см. раздел «Готовые программы и релизы».

## Куда писать, если ничего не помогло

Контакты разработчика — в разделе «О программе». Приложите файл `kolibri-forge.log`: кнопка «Журнал на диске» на вкладке «Журнал» открывает его папку.
